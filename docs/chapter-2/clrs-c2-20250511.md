# 第2章 ソートで学ぶアルゴリズムの設計と解析

## 2.1 挿入ソート

前回は、以下のようなことを学んだ。
- アルゴリズムとは何か？
- アルゴリズムを学ぶと何がうれしいのか？
- どう評価するのか？
- 何が解決できないのか？

具体的なアルゴリズムの最初の例として、挿入ソートを紹介したい。手持ちのトランプを整列させる操作に似ていて、もっとも単純なソートアルゴリズムと言える。それでは具体的にどう動作するのか見ていきたい。

### 2.1.1 アルゴリズムの動作

未整列の要素を1つずつ取り出し、すでに整列済みの部分の正しい位置に挿入していく。

```
INSERTION-SORT(A, n)
1  for i = 2 to n
2      key = A[i]
3      j = i - 1
4      while j > 0 and A[j] > key
5          A[j+1] = A[j]
6          j = j - 1
7      A[j+1] = key
```

#### 演習 2.1: 挿入ソートを手で追う

配列 $[5, 2, 4, 6, 1, 3]$ に対して、外側ループの各反復が終わった直後の配列を書け。

| 反復 | `key` | 反復終了後の配列 |
|:----:|:-----:|:----------------|
| $i=2$ |       |                 |
| $i=3$ |       |                 |
| $i=4$ |       |                 |
| $i=5$ |       |                 |
| $i=6$ |       |                 |


### 2.1.2 ループ不変式と正当性

アルゴリズムが正しく動くことを証明するための道具。ループの各ステップで成り立つ性質を「ループ不変式」と呼び、初期・維持・終了の3条件で正しさを示す。数学的帰納法にとても似ている。

挿入ソートでは、外側の for ループについて次のループ不変式を考える。

> 各反復の開始時点で、部分配列 $A[1..i-1]$ は整列済みであり、もともと $A[1..i-1]$ に含まれていた要素をちょうど含んでいる。

初期:ループの1回目が始まる前に不変式が成り立つか？

$i=2$ のとき、部分配列 $A[1..1]$ は要素を1つしか持たないため、すでに整列済みである。したがって不変式は成り立つ。

維持:ループの $n$ 回目に不変式が成立するとき、$n+1$ 回目に不変式が成り立つか？

反復の開始時点で $A[1..i-1]$ が整列済みだと仮定する。while ループは $A[i]$ の値を `key` として保存し、`key` より大きい要素を右に1つずつずらして、`key` を正しい位置に挿入する。その結果、反復の終了時には $A[1..i]$ が整列済みになり、含まれる要素も変わらない。よって次の反復の開始時にも不変式は成り立つ。

終了:ループが終わったとき、不変式から言えることがアルゴリズムの正しさを示しているか。

for ループが終了すると $i=n+1$ である。不変式より、部分配列 $A[1..n]$ は整列済みで、もとの配列と同じ要素を含んでいる。したがって、配列全体が正しくソートされている。

これでアルゴリズムの正しさを検証できる。

#### 演習 2.2: while ループの不変式を考える

挿入ソートの内側の while ループについて、成り立ちそうなループ不変式を1つ考えよ。

ヒント：while ループの途中では、`key` より大きい要素が右にずらされている。どの範囲がどのような状態になっているかに注目する。



## 2.2 アルゴリズムの解析

アルゴリズムの性能を定量的に評価する方法を定める。

### 2.2.1 計算モデル（RAMモデル）

RAMモデルでは、プロセッサは命令を1つずつ順番に実行し、加減乗除などの算術演算・メモリへの読み書き・条件分岐のいずれも一定時間（$O(1)$）でできると仮定する。現実のCPUにはキャッシュや分岐予測があるが、それらを無視することで「どの計算機でも通用する」アルゴリズムの性能比較が可能になる。

### 2.2.2 入力サイズと実行時間の定義

**入力サイズ** $n$ の定義は問題によって異なる。ソートなら要素数、グラフ問題なら頂点数 $|V|$ と辺数 $|E|$ の両方、整数演算なら値そのものではなくビット数が基準になる。

**実行時間**は、各行のコスト $c_i$ と実行回数の積の総和として定式化する。INSERTION-SORT を例に各行を分析する。

```
INSERTION-SORT(A, n)
1  for i = 2 to n
2      key = A[i]
3      j = i - 1
4      while j > 0 and A[j] > key
5          A[j+1] = A[j]
6          j = j - 1
7      A[j+1] = key
```

| 行 | コスト | 実行回数 |
|:--:|:------:|:--------:|
| 1  | $c_1$  | $n$ |
| 2  | $c_2$  | $n-1$ |
| 3  | $c_3$  | $n-1$ |
| 4  | $c_4$  | $\displaystyle\sum_{i=2}^{n} t_i$ |
| 5  | $c_5$  | $\displaystyle\sum_{i=2}^{n} (t_i - 1)$ |
| 6  | $c_6$  | $\displaystyle\sum_{i=2}^{n} (t_i - 1)$ |
| 7  | $c_7$  | $n-1$ |

ここで $t_i$ は、$i$ 番目の外側ループにおける while 条件の評価回数（挿入位置が見つかるまでの比較回数）。

全行を合計すると実行時間は：

$$
T(n) = c_1 n + c_2(n-1) + c_3(n-1) + c_4\sum_{i=2}^{n}t_i + c_5\sum_{i=2}^{n}(t_i-1) + c_6\sum_{i=2}^{n}(t_i-1) + c_7(n-1)
$$

$t_i$ の値は入力の並び方に依存するため、同じ $n$ でも実行時間は異なりうる。これが次節で最悪・最良・平均ケースを区別する理由になる。

### 2.2.3 最悪・最良・平均ケース

同じアルゴリズムでも入力の並び方によって実行時間が変わる。2.2.2 の $T(n)$ の式で $t_i$ に具体的な値を代入することで各ケースが計算できる。

#### 演習 2.3: 入力による実行時間の違い

次の2つの入力に対して、挿入ソートの while 条件が何回評価されるかを考えよ。

1. $[1, 2, 3, 4, 5]$
2. $[5, 4, 3, 2, 1]$

それぞれについて、各反復の $t_i$ と $\sum_{i=2}^{n} t_i$ を求めよ。

**最良ケース（配列が昇順にソート済み）**

while 条件を1回評価するとすぐ偽になるため $t_i = 1$。

$$
\sum_{i=2}^{n} t_i = n - 1, \qquad \sum_{i=2}^{n}(t_i - 1) = 0
$$

$$
T(n) = (c_1 + c_2 + c_3 + c_4 + c_7)n - (c_2 + c_3 + c_4 + c_7) = an + b
$$

$n$ の1次式なので $\Theta(n)$。

**最悪ケース（配列が逆順）**

毎回先頭まで比較するため $t_i = i$。

$$
\sum_{i=2}^{n} t_i = \frac{n(n+1)}{2} - 1, \qquad \sum_{i=2}^{n}(t_i - 1) = \frac{n(n-1)}{2}
$$

$$
T(n) = an^2 + bn + c
$$

$n$ の2次式なので $\Theta(n^2)$。

**平均ケース**

各要素が等確率でどこにでも挿入されると仮定すると、平均的に $t_i \approx i/2$。結局 $\Theta(n^2)$ になり最悪ケースと同じオーダーになる。

**なぜ最悪ケースを基準にするか**

- 実行時間の上界を保証できる（「どんな入力でもこれ以上かからない」と言える）
- 最悪ケースが頻繁に起きるアルゴリズムも多い
- 平均ケースは入力の確率分布の仮定が必要で、定義が難しい

### 2.2.4 増加のオーダー

定数倍の違いを無視し、入力サイズ $n$ が大きくなったときの実行時間の増え方（$\Theta$ 記法）に注目する。

**Θ の定義**

$$
\Theta(g(n)) = \bigl\{\, f(n) \mid \exists\, c_1, c_2, n_0 > 0 \text{ s.t. } \forall n \geq n_0,\ c_1\, g(n) \leq f(n) \leq c_2\, g(n) \,\bigr\}
$$

「上からも下からも定数倍で挟める」ときに $f(n) = \Theta(g(n))$ と書く。

**低次項・定数係数を捨てられる理由**

2.2.3 の最悪ケース $T(n) = an^2 + bn + c$ を例に考える。$n$ が十分大きくなると $n^2$ が他の項を圧倒し、

$$
\frac{T(n)}{n^2} = a + \frac{b}{n} + \frac{c}{n^2} \;\to\; a \quad (n \to \infty)
$$

つまり $c_1 = a/2$、$c_2 = 2a$ のような定数をとれば $c_1 n^2 \leq T(n) \leq c_2 n^2$ が成り立つため、$T(n) = \Theta(n^2)$ と書ける。

**代表的なオーダーの増加速度**

$$
\Theta(1) \prec \Theta(\log n) \prec \Theta(n) \prec \Theta(n \log n) \prec \Theta(n^2) \prec \Theta(n^3) \prec \Theta(2^n)
$$

挿入ソートの最悪ケースは $\Theta(n^2)$ に位置する。

## 2.3 アルゴリズムの設計：分割統治法

問題を小さな部分問題に分割して解き、結果を統合するという設計戦略。

### 2.3.1 分割統治のアプローチ

3ステップで問題を解く。

- **分割（Divide）**：元の問題を同じ種類の小さな部分問題に分ける
- **統治（Conquer）**：各部分問題を再帰的に解く。十分小さければ直接解く
- **統合（Combine）**：部分問題の解を合わせて元の問題の解を作る

**現実の例：5000字の作文**

5000字の作文をいきなり書き始めるのは難しい。まず章立てを作って分割し、各章をさらに節・項に分ける（分割）。最小単位になったら内容を直接書く（統治）。書き上がった項を節へ、節を章へ、章を作文全体へとつなぎ合わせて完成させる（統合）。統合ステップは単純な連結ではなく、流れや接続を作る非自明な作業になっている点が重要。

### 2.3.2 マージソート

マージソートは分割統治の典型例。「2つの整列済みの山を合わせるのは簡単」という観察を再帰的に利用する。

**現実の例：トランプの合わせ**

整列済みの2つのトランプの山があれば、それぞれの先頭を比べながら小さい方を取り出すだけで整列済みの1つの山が作れる。マージ操作はこれそのもの。

**動作例：** $[5, 2, 4, 6, 1, 3]$ をソートする。

```
分割
[5, 2, 4, 6, 1, 3]
  ↓
[5, 2, 4]   [6, 1, 3]
  ↓               ↓
[5, 2] [4]   [6, 1] [3]
  ↓               ↓
[5][2] [4]   [6][1] [3]

統合（マージ）
[2, 5] [4]   [1, 6] [3]
  ↓               ↓
[2, 4, 5]   [1, 3, 6]
        ↓
  [1, 2, 3, 4, 5, 6]
```

**疑似コード：**

```
MERGE-SORT(A, p, r)
1  if p < r
2      q = ⌊(p + r) / 2⌋
3      MERGE-SORT(A, p, q)
4      MERGE-SORT(A, q+1, r)
5      MERGE(A, p, q, r)
```

```
MERGE(A, p, q, r)
1   nL = q - p + 1                   // 左半分の長さ
2   nR = r - q                       // 右半分の長さ
3   L[0..nL-1] と R[0..nR-1] を新しい配列として確保
4   for i = 0 to nL - 1
5       L[i] = A[p + i]              // 左半分をコピー
6   for j = 0 to nR - 1
7       R[j] = A[q + 1 + j]         // 右半分をコピー
8   i = 0
9   j = 0
10  k = p
11  while i < nL and j < nR         // 両方に残りがある間
12      if L[i] <= R[j]
13          A[k] = L[i]
14          i = i + 1
15      else
16          A[k] = R[j]
17          j = j + 1
18      k = k + 1
19  while i < nL                    // 左に残りがあれば書き戻す
20      A[k] = L[i]
21      i = i + 1
22      k = k + 1
23  while j < nR                    // 右に残りがあれば書き戻す
24      A[k] = R[j]
25      j = j + 1
26      k = k + 1
```

### 2.3.3 漸化式による解析

マージソートの実行時間 $T(n)$ を漸化式で表す。

$$
T(n) = \begin{cases} \Theta(1) & (n = 1) \\ 2T(n/2) + \Theta(n) & (n > 1) \end{cases}
$$

$2T(n/2)$ は半分のサイズの部分問題2つ、$\Theta(n)$ はマージのコスト。

**再帰木で考える：**

```
レベル 0:          Θ(n)                  ← 合計 Θ(n)
レベル 1:    Θ(n/2)  Θ(n/2)              ← 合計 Θ(n)
レベル 2:  Θ(n/4)×4                      ← 合計 Θ(n)
   ...
レベル log n:  Θ(1) × n                  ← 合計 Θ(n)
```

各レベルの仕事量が $\Theta(n)$ で一定、レベル数が $\log n$ なので：

$$
T(n) = \Theta(n \log n)
$$

#### 演習 2.4: 再帰木を描く

$n=8$ のとき、マージソートの再帰木を描き、各レベルの仕事量の合計を求めよ。

| レベル | 部分問題の個数 | 1個あたりのサイズ | そのレベルの仕事量 |
|:------:|:--------------:|:------------------:|:------------------:|
| 0 |                |                    |                    |
| 1 |                |                    |                    |
| 2 |                |                    |                    |
| 3 |                |                    |                    |

最後に、すべてのレベルの仕事量を合計するとどのオーダーになるかを答えよ。

挿入ソートの最悪ケース $\Theta(n^2)$ と比べると、$n$ が大きくなるにつれてマージソートの方が圧倒的に速い。

**置換法（帰納法）で考える：**

再帰木は直感的だが「なんとなく正しそう」という域を出ない。置換法は「答えを推測して数学的帰納法で証明する」アプローチ。

$T(n) \leq cn\log n$ が成り立つと仮定して証明する。

帰納的なステップ：漸化式に代入する。

$$
T(n) = 2T(n/2) + \Theta(n) \leq 2 \cdot c\frac{n}{2}\log\frac{n}{2} + \Theta(n)
$$

$$
= cn(\log n - \log 2) + \Theta(n) = cn\log n - cn + \Theta(n)
$$

$\Theta(n) \leq cn$ を満たす定数 $c$ をとれば $-cn + \Theta(n) \leq 0$ となり、

$$
T(n) \leq cn\log n
$$

が成り立つ。再帰木で「たぶん $\Theta(n \log n)$」と見当をつけ、置換法で確認するという使い方が多い。

## 予想される質問

**Q1. 挿入ソートは遅いのに、なぜわざわざ学ぶ？**

$\Theta(n^2)$ は確かに遅いが、$n$ が小さいときは定数係数が小さいため実用上マージソートより速いことがある。実際、多くのソートライブラリは小さい部分配列に対して内部的に挿入ソートを使っている。また、ほぼ整列済みのデータに対しては最良ケース $\Theta(n)$ になる。「常にマージソートが優れている」わけではない。

---

**Q2. O記法とΘ記法はどう使い分ける？**

$\Theta$ は上界と下界の両方を与える（tight bound）。$O$ は上界のみ。実行時間が具体的に求まっている場合は $\Theta$ を使うのが正確。「この問題を解くには最低でも $\Omega(n \log n)$ かかる」のような下界の主張には $\Omega$ 記法を使う。$O$ は「最悪でもこれ以下」と保証したいときや、上界しかわからないときに使う。

---

**Q3. 最悪ケースが $\Theta(n^2)$ でも平均ケースが速ければ実用上は問題ないのでは？**

場合による。平均ケースの計算には「入力がランダムに分布する」という仮定が必要で、現実の入力がその仮定を満たすとは限らない。例えば既にほぼ整列済みのデータが来ることが多い場面では、平均ケースの分析は当てにならない。セキュリティ上クリティカルな場面（ハッシュテーブルへの攻撃など）では最悪ケースの保証が重要になる。

---

**Q4. マージソートはいつも挿入ソートより速い？**

$n$ が十分大きければ速いが、小さい $n$ では逆になる。$\Theta$ 記法は定数係数を無視するため、実際の速度は隠れた定数に依存する。マージソートはメモリの確保やコピーのオーバーヘッドがあるため、$n$ が小さいとき（目安として $n \leq 20$ 程度）は挿入ソートの方が速いことが多い。

---

**Q5. マージソートの欠点は？**

追加メモリが $\Theta(n)$ 必要な点。MERGE の中で左右の部分配列を一時配列にコピーするため、入力とは別に $n$ に比例したメモリを使う。メモリが制約される組み込み環境では問題になる。「追加メモリを使わないソート（in-place sort）」が求められる場面では別のアルゴリズムを選ぶ。

---

**Q6. 置換法で「答えを推測する」のはどうやって？**

主に2つの方法がある。①再帰木を描いて「たぶんこのオーダー」と見当をつける（2.3.3で行った手順）。②似た漸化式の既知の解を参照する。推測が外れたら定数を調整したり、より強い・弱い主張に変えて再試行する。置換法は推測なしには動かないため、再帰木との組み合わせが基本になる。
